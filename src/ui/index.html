    Nova aplicação (API Key virtual)

    Cada cliente (Trae, Cursor, VS Code, N8N...) usa a mesma Base URL do gateway e a própria chave. O modelo e o provedor são controlados aqui, em tempo real, sem mexer nas configurações da ferramenta.

    Como funcionam as portas: a porta direta (porta 3005) deixa cada ferramenta escolher o modelo livremente. A porta gateway (porta 3006) ignora o modelo enviado pelo cliente e usa o modelo definido aqui no painel — o provedor é resolvido automaticamente, sem seleção manual. Configure suas IDEs com a Base URL do gateway + a chave virtual.

    O que é o DeepProxy (em 2 frases)

    O DeepProxy é um telefone entre dois mundos: ele roda no seu computador e liga programas de edição de código (Trae, Cursor, VS Code) aos modelos de IA (Gemini, DeepSeek, Qwen e outros). Você não precisa configurar nada de programação — basta seguir o passo a passo.

    Dicionário rápido (termos que aparecem daqui pra baixo)

    • IDE — o programa em que você escreve código (Trae, Cursor, VS Code).
    • Modelo — a "cabeça" da IA (ex.: Gemini, DeepSeek, Qwen).
    • Provedor — a empresa que fornece o modelo (ex.: Google dá o Gemini).
    • Chave de API — uma senha que permite usar um modelo. Cada conta tem uma.
    • Porta — um número de "porta" por onde o pedido entra. Este painel usa a 3005 e a 3006.
    • Gateway — aqui é o "central de distribuição": ele decide qual modelo atende cada pedido.

    1. Ligar sua IDE ao DeepProxy

    1. Abra as configurações de modelo da sua IDE e escolha OpenAI-compatible (em algumas aparece como "Custom" ou "Custom Provider").
    2. Em Base URL, cole um destes dois endereços:
      - Você não quer escolher modelo toda hora: use a porta do gateway (http://localhost:3006/v1) — quem decide o modelo é o painel.
      - Você prefere escolher o modelo na própria IDE: use a porta direta (http://localhost:3005/v1).
    3. Na aba Apps (Gateway), crie uma chave virtual (é só um nome de identificação) e cole em API Key na IDE.
    4. Escolha o modelo auto na IDE e comece a conversar. É só isso.

    2. Escolher qual modelo vai responder

    • auto (recomendado) — o DeepProxy escolhe o melhor modelo pela sua conta de API (Gemini, Anthropic, Groq...). Se uma falhar, ele tenta as outras. Somente no último caso usa o acesso grátis pelo navegador.
    • auto-free — usa só os gratuitos pelo navegador (DeepSeek, Qwen, Gemini Web). Funciona, mas pode ser mais lento e nem sempre executa ferramentas.
    • Um modelo específico — amarra aquele app/teste sempre ao mesmo modelo.

    Para saber qual modelo atendeu o último pedido, olhe o cabeçalho X-AutoRouter-FinalModel na resposta (ou nos logs).

    3. Adicionar contas (chaves de API)

    1. Vá na aba Conexão e clique em + Novo provedor (ex.: Gemini).
    2. Cadastre as contas que você tiver — dá pra ter 3 chaves do Gemini, por exemplo.
    3. Quando um pedido chega, o proxy usa cada chave por vez: se a primeira estourou o limite (a resposta é o código 429), ele "descansa" essa chave por um tempo e tenta a próxima no mesmo pedido.
    4. Se todas estiverem descansando, você recebe um aviso claro. É só esperar o limite renovar ou cadastrar outra conta.

    O painel mostra o status de cada chave (ativa / descansando). Quando o tempo de descanso acaba, a chave volta sozinha — e esse estado continua valendo mesmo se você reiniciar o programa (fica salvo no providers.json).

    4. Chat direto (sem abrir a IDE)

    Na aba Chat (ou no endereço /chat) você conversa com a IA direto pelo proxy — útil para testar ou quando a IDE não está aberta.

    5. Conferir se está tudo funcionando

    A aba Testar API manda uma conversa de teste de verdade para a IA, usando o modelo que você escolher. Em segundos você vê se a conexão funciona, se as chaves estão ok e o que a IA respondeu.

    6. Auto Router (o "chefe" que decide o modelo)

    • Política de custo — como escolher o modelo: Balanceado (padrão), Econômico, Qualidade, Só gratuitos ou Só pagos.
    • Circuit breaker — se um modelo vem falhando na prática, ele sai da disputa por um tempo e volta sozinho quando está melhor.
    • Catálogo — as "notas" que o chefe usa para decidir qual modelo é melhor para cada tarefa.

    7. Modelos que rodam no seu PC (Ollama / LM Studio)

    A aba Modelos Locais acha sozinha os modelos rodando na sua máquina, mostra se estão saudáveis e pode recorrer à nuvem automaticamente quando o modelo do PC falha ou demora.

## 5. CORREÇÃO
- Mínima: só o que explica o sintoma observado.
- Toda correção vem acompanhada de 1 teste que falhava antes e passou depois.

    9. Se algo der errado (o que essas mensagens significam)

    • "atingiu a cota" (nos logs) — uma chave acabou o limite e o proxy pulou para a próxima. Normal, não é erro.
    • [tool-error] — sua IDE recusou uma ação da IA (ex.: editar um arquivo). Leia a mensagem e tente de novo.
    • X-AutoRouter-FinalModel — o nome do modelo que respondeu (aparece nos logs ou no cabeçalho da resposta).
    • 429 "Todas as contas..." — todas as chaves desse provedor estão descansando. Cadastre mais uma ou espere o limite renovar.

    Descarta mensagens antigas quando o contexto fica cheio.

    Impacto: preserva a essência, mas pode perder detalhes específicos (números, nomes, trechos de código).

    afeta precisão

    Limita respostas de ferramentas a 4.000 caracteres.

    Limita cada mensagem de ferramenta (role tool/function) a 4.000 caracteres. Quando o resultado é cortado, o modelo vê "...[truncado: N chars]" no final.
    Impacto: se uma tool retornar dados extensos (código, JSON, listagens), o modelo pode perder informação crítica para a tarefa.

    baixo risco

    sem impacto

    Acelera respostas mantendo o início do prompt em cache. Sem perda de qualidade.

    Mantém o prefixo do prompt em ordem estável para cache automático. No Anthropic ativa cache_control (10-25% economia).

    sem impacto

    Guarda em memória (60s, máx 200 entradas) respostas NÃO-streaming idênticas. Evita retrabalho em chamadas repetidas.
    Impacto: zero.

    informativo

    Mostra no log quantos tokens cada requisição usa.

    Registra no console a estimativa de tokens por requisição.
    Impacto: zero — apenas gera log.

    médio risco

    Preserva as mensagens mais importantes ao truncar contexto.
